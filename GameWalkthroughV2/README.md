# 游戏攻略助手

从网页（游民星空图文攻略）下载攻略**图片**，插入游戏助手服务端 vision 服务建立索引；检测到玩家启动游戏后，以 ~10 FPS 截取游戏窗口画面并匹配当前场景，把匹配图片对应的**页面 URL 与图片位置**推送给本地 webserver；webserver 通过 SSE 把目标转发给浏览器，浏览器页面由**顶栏（游民星空 logo + 攻略标题）+ frame** 组成，frame 打开推送的攻略页面并**自动定位到匹配的攻略内容位置**。

> webserver 不再抓取/过滤/分页攻略内容。浏览器同源策略禁止脚本滚动跨域
> frame，因此 frame 经由 webserver 的**同源透传代理**（`/proxy?url=...`）打开
> 原始攻略页：只注入 `<base>` 与 `no-referrer`、改写站内链接，内容不做任何
> 过滤——这是“不过滤内容”与“可定位到内容位置”能同时成立的方式。

```
┌───────────────────┐   图片插入/查询   ┌──────────────────────┐
│  桌面客户端 (app)   │ ───────────────▶ │  游戏助手服务端 vision │
│  检测游戏/截图/推送  │ ◀─────────────── │  insert / query / build│
└─────────┬─────────┘                   └──────────────────────┘
          │ 推送 {游戏, 页面URL, 图片位置, 标题}
          ▼
┌───────────────────┐  SSE 推送目标        ┌──────────────────────┐
│  webserver (内嵌)  │ ──────────────────▶ │  手机/电脑/平板 浏览器  │
│  转发推送/同源代理  │ ◀── /proxy 透传页面 ─│  顶栏 + frame 定位内容 │
└───────────────────┘                     └──────────────────────┘
```

## 安装

```bash
pip install -r requirements.txt
```

需要提前运行**游戏助手服务端**（新版默认 `http://127.0.0.1:22919`，vision 接口见
`docs/游戏助手服务接口说明.pdf` 第 5 章），并完成一次攻略下载与导入。
客户端与下载脚本未显式指定地址时自动探测：22919 不通则回退旧版端口 9190。

## 快速开始

### 1. 配置游戏进程映射

编辑 `config/game_processes.json`，把想识别的游戏进程映射成游戏名：

```json
{
  "eldenring": "艾尔登法环"
}
```

`config/exclude_processes.json` 里是 GPU 利用率高但**不是游戏**的进程（浏览器、
播放器、IDE 等），会被直接跳过。

**每游戏视觉阈值**（可选）：编辑 `config/game_thresholds.json`，键为游戏名
（与 `game_processes.json` 里的游戏名一致），未配置的游戏使用默认值 0.80/0.01：

```json
{
  "明末：渊虚之羽": {"threshold": 0.80, "threshold_2": 0.01},
  "识质存在": {"threshold": 0.85, "threshold_2": 0.10}
}
```

条目可只写其中一个字段；文件修改后保存即生效（无需重启，客户端每次查询前
自动检测文件变化并重新加载）。加载失败（如 JSON 写错）时什么都不做，沿用
上一次成功加载的配置。优先级：命令行 `--query-threshold` 显式指定 > 该文件
> 默认值。

### 2. 下载攻略图片

```bash
python -m app.game_walkthrough_downloader "生化危机4重制版" --images-only
```

只下载图片，不下载文本。生成 `walkthrough/<游戏>/images.json`，
记录每张图片的原始 URL（src）、本地文件（local）、在页面中的顺序（index）
以及所属章节标题（section）。

> 已用《生化危机4重制版》实测（`https://www.gamersky.com/handbook/202303/1575258.shtml`）：
> 攻略共 93 章、895 个图文页。游民星空翻页器实际是 `<span class="pagecss">`
> （旧版页面才是 `div.page_css`），下载器对两种均已兼容。
> 若你的网络需要代理，请通过 `HTTPS_PROXY` / `HTTP_PROXY` 环境变量设置，
> 不要写进代码。

**新版“攻略路书”页（2026-09 改版）**：部分新攻略的 `.shtml` 地址只是跳转壳，
页内 `#redirectTips` 的 `data-link` 指向真正的路书页
（`tools/guide-map/roadbooks/<id>`，全部内容内联为 `reader-node-card` 节点卡）。
下载器会自动跟随跳转，并把每个节点卡当作一个虚拟页处理：`images.json` 里
`url` 记为 `<路书页>#reader-node-<id>`（续传/scene_id 按节点区分），图片的
`section` 为节点标题（如 “A1 序章及概要”）。旧版页面行为不变。

**路书页在网页端的展示适配**：路书页是桌面排版（固定 1200px 布局），手机上
没法看。代理对路书页注入裁剪样式（`_ROADBOOK_STRIP_CSS`）：隐藏顶部导航栏
（`.Top` / `.gamersky-nav-wrapper`）、游戏链接条、广告、左侧目录导航
（aside.roadbook-nav）、右侧地图导航（.reader-progress-wrapper）、tab 栏、
页脚与“收起/展开目录”悬浮按钮，只保留中间图文内容，并把正文列从
固定 1000/660px 放宽为自适应宽度；手机上查看器对路书页按**自适应铺满**展示
（不做等比缩放，字号正常可读）。目录跳转使用查看器自己的“目录列表”下拉：
路书页列出全部节点卡，选中后**不重载页面**（路书页 3MB+），直接滚动到对应
节点卡的图文位置；同页内的场景推送同样只换 `#片段` 定位，不整页刷新。
目录项地址基于去片段的页面地址生成（`/api/toc`），加载完成后下拉即高亮当前
所处章节；点选带 `#片段` 的路书地址在加载完成后也会自动定位到目标节点
（目标节点暂未渲染时短暂轮询等待，绝不整页重载或退回页首）。
底部“上一页/下一页”在路书页里翻的是**上一段/下一段文本**（节点卡），
边界处提示“已经是第一/最后一章节”。“回到场景”按钮按**文档**（不含 `#片段`）
判断是否仍在推送页：路书页内的定位不改变 frame 地址，点击后直接在当前文档
内按场景图片重新定位（不会误判为已翻页而整页重载、退到节点卡开头）。
手动翻段/目录跳转会**作废未完成的定位校正**（旧场景的延迟校正不会把页面拽
回去）；场景图片暂未渲染时先定位到所在节点，图片出现后**自动升级**到图片位置。
“回到场景”的图片定位有双保险：优先按图片地址匹配；匹配不到（站点懒加载/
重渲染改写地址）时按推送携带的**图片序号**取节点正文里的第 N 张图。
回到场景与场景推送是**图片级指令**，不会被目录跳章的节点级拦截截胡（站点
改写自身地址后仍按同一文档处理，直接在文档内重新定位到图片）。
识别推送（navigate/game-detected）携带 `image_index` 并持久化：重启 app 后
再检测到同一游戏时**恢复上次浏览位置**（含图片定位），不会被“攻略首页”拉回
第一章；全新游戏仍推送首页。

### 3. 导入 vision 服务

```bash
python -m app.walkthrough_service_importer "walkthrough/艾尔登法环/images.json" \
    --instance-id "艾尔登法环" --images-json
```

把每个页面的图片作为一条 vision scene 插入并 build，同时生成
`scene_map.json`，用于把 vision 返回的 scene_id/picture_id 反查回
“页面 URL + 图片位置”。

### 4. 启动客户端

```bash
python run_app.py
# 或指定游戏名：跳过游戏检测，直接下载/导入攻略并识别全屏画面
python run_app.py 艾尔登法环
```

- 自动启动内嵌 webserver（端口 22818，可 `--web-port` 修改）。
- **指定游戏名模式**（传入位置参数 `游戏名`）：不启动 GPU 检测，弹“指定游戏”
  提示后立即自动下载 + 导入该游戏攻略，并抓取**全屏画面**（不绑定游戏窗口）
  送 vision 识别，适合无 GPU 数据或窗口检测不出的场景。
- 检测到游戏时：左上角弹出“检测到游戏”提示，并把该游戏设为网页的当前游戏。
- 若该游戏尚未导入，客户端会**自动下载 + 导入**攻略（可 `--no-auto-bootstrap` 关闭），
  采用**边下边导入**：每下载完一页立即 插入新场景 + 构建索引，第一页构建完成后
  截图识别即开始并自动定位到攻略位置——玩家先玩起来，剩余页面在后台继续
  边下边导入（进度条按已完成的页数推进）。
  **中途退出再启动会续传**：正常完成时下载状态会带 `finished` 标记；未完成时
  再次识别到同一游戏会自动继续下载剩余页面（已下载的页/图/场景不重复处理）。
  **切换游戏以识别结果为准**：检测到新游戏时页面切到新游戏的攻略位置；
  上一款游戏的迟到推送（切换瞬间在途的识别查询、残留的自动导航）会被
  webserver 忽略，不会把页面拽回旧游戏。
  就绪与否以**本地 `scene_map.json`** 为准：服务端实例还在但本地攻略文件被删
  （误删 `walkthrough/`、`data/` 目录等）时视为未就绪并自动恢复——`images.json`
  还在就直接重插 + build 重建（不走网络），全无则重新下载。
  首页构建完成前**不开始截图识别**——服务端实例在 build 前就已创建，不对着
  建到一半的索引反复发无效查询；构建完成后自动把攻略页面**定位到位**：首次
  导入跳到攻略第一页；之前展示过该游戏的恢复**上次浏览的页面**（含定位图片
  与章节），该页在本次攻略里已不存在（换文/改版）时回退第一页。
- 以 10 FPS 截图放入单槽队列，上一轮 vision 查询结束后取队列中**最新**的一帧
  发送，其余丢弃。
- 匹配成功后把 `{游戏, 页面URL, 图片位置}` 推送给 webserver，并弹出
  “跳转攻略页面”提示。
- 鼠标移到**显示器右上角**时，自动从右侧滑入**扫码访问面板**（二维码 + 局域网
  地址），手机/平板扫码即可打开攻略页面；鼠标移开自动收回（详见下文）。

### 5. 打开网页查看攻略

本机浏览器访问 `http://127.0.0.1:22818`；手机/平板建议直接扫电脑屏幕右上角的
二维码（或手动访问 `http://<本机IP>:22818`，需放行防火墙）。

页面结构：
- **顶栏（固定）**：`游民星空 × Intel AI游戏助手` 联合标识（宽度不足时字号
  自适应缩小，不换行、不被按钮遮挡），右侧“回到场景”按钮。
- **下载进度条（下载中才出现）**：攻略正在下载时顶栏下方显示一条进度横幅
  （游戏名 + 阶段 + 百分比 + 进度条 + 当前行详情），下载完成/失败后短暂提示
  几秒自动收起，平时完全不占版面（详见下文“攻略下载进度展示”）。
- **底部导航栏（固定）**：上一页 | 目录列表 | 下一页。上一页/下一页按当前
  页面前后翻页（第一页/最后一页时忽略）；目录列表来自攻略页的“文章内容导航”，
  保持原有顺序，当前章节会被选中，展开时列表自动滚动到当前章节，选择章节
  直接跳转。手动翻页/跳章不触发场景定位。
- **其余部分**：一个 frame，经 `/proxy` 打开 webserver 推送的攻略页面原始 URL，
  加载完成后自动**定位到推送的内容位置**（优先滚动到匹配的那张攻略图片，
  没有图片目标时定位到攻略正文区 `.Mid2L_con`，跳过站点头部/导航）。

行为：
- webserver 收到新的 URL/图片位置时，通过 SSE 通知浏览器 frame **自动打开并
  定位**；URL 未变时只重新定位，不重载页面。
- 线上攻略页的截图 `src` 全是 blank 占位图（真实地址在 `data-src`）。定位时
  查看器会先把正文图片**强制换成真图**（绕过站点懒加载），等目标图片渲染出
  真实高度后再滚动，并在 1.5s/3.5s/6s 多次校正布局漂移——用户一旦手动滚动
  或触摸，立即停止校正。
- **自由浏览**：只有"新场景推送"和手动点"回到场景"才会定位/跳转；用户在
  frame 内自行点"下一页"、切换章节不会被拉回。
- 定位结果会在页面底部短暂提示（使用场景的章节名，如
  `已定位到「第6页：佛源镇-含光禅院」`），便于确认是否命中。
- **手机/窄屏适配**：手机上自动把攻略页 URL 映射到游民星空 **wap 手机版**
  （`Content-<id>[_N].html`，排版自适应、字号正常，图片 ID 与 PC 版一致所以
  定位不受影响）；无法映射的地址退回 PC 版按 1200px 设计宽等比缩放展示。
  桌面端始终使用 PC 版原样展示。
- 页面内 gamersky 域的 XHR/fetch（评论区、点赞数等）会被自动转发到 `/proxy`
  恢复同源语义，否则会被 CORS 拦截导致评论区加载失败。
- frame 内点击站内翻页链接仍走代理（保持可定位）；中途跳去跨域页面后点
  “回到场景”会重新经代理打开。
- 退出后重新打开网页 → 恢复该游戏上次的推送目标；从未展示过任何游戏时显示
  “进入游戏后开始展示攻略”。

> 代理仅透传原始页面（白名单限 `*.gamersky.com`），不解析、不过滤、不改写
> 正文内容；原始页面的广告/导航会原样显示。

## 攻略下载进度展示

攻略下载（客户端自动下载/导入，以及服务端实例被删后的**重新 insert + build**）
进行中时，**打开中的攻略页面**（`http://127.0.0.1:22818`，含左上角浮窗）顶部会
实时显示进度，用户不必再猜“到底在下没在下”。重新导入没有下载阶段，横幅直接
从“导入场景图片”起报：

- **数据链路**：下载方把进度写入共享状态文件 `data/download_status.json`
  （`app/download_progress.py`，含阶段/百分比/详情，进度只增不减；心跳线程
  持续刷新时间戳，写入进程意外退出后 45 秒即被判为“下载已中断”，页面不会
  永远挂一个假进度条）→ 内嵌 webserver 每秒轮询该文件，变化即通过 SSE
  广播 `download_progress` 事件 → 页面实时刷新横幅；页面首次加载时也会主动
  `GET /api/download-status` 拉一次。
- **进度阶段**：搜索攻略 → 下载攻略页面（按页码推进，共 10%→82%）→ 导入
  场景图片（按场景数推进）→ 构建图片索引（按服务端构建事件实时推进，
  96%→99%）→ 完成；总页数未知时进度条以往复滑动动画示意。
- **终态提示**：完成显示“《游戏》攻略已就绪”、失败/中断显示原因，几秒后
  自动收起；页面打开很久之前留下的旧终态不会打扰。

### 下载失败自动重试与手动重试

- **自动重试**：下载攻略（页面/图片）与导入（访问游戏助手服务端）的全部网络
  请求失败（超时/连接失败/服务端 5xx）时，自动**间隔 20 秒重试 3 次**
  （`app/net_retry.py`），重试过程会实时显示在进度横幅的详情行里。
- **连续失败熔断**：重试后仍连续 3 张图片下载失败，判定网络不可用，中止本次
  下载并报错（避免对上千张图片逐张做无谓重试）。
- **页面“重试”按钮**：失败/中断后进度横幅**常驻不自动收起**，右侧提供
  “重试”按钮。点击后 `POST /api/download-retry` → webserver 转给客户端 →
  客户端重新发起下载/导入，**自动从失败处续传**（已完成的页面/图片/场景不
  重复下载，详见 images.json / download_*_state.json 的续传机制）。
  独立 webserver（客户端未运行）点击重试会提示无法自动重试。

## 文件日志

运行事件写入 `GameWalkthroughV2/logs/game-assistant-YYYYMMDD.log`
（**每天一个文件**，多进程按天共用一份，追加写入）：

- **记录范围**：攻略下载过程（搜索/逐页/逐图）、导入过程（vision 场景插入、
  索引构建）、webserver 收到的推送（navigate/game-detected/下载重试请求）、
  打开网页的过程（查看器页面、代理抓取的每个 URL 及耗时/结果）、下载状态的
  每次广播。
- **自动清理**（`app/file_logging.py`，启动时与每次跨天各执行一次）：
  超过 **30 天**的日志压缩为 `.gz`（删除原文件）；超过 **半年（182 天）**的
  压缩包直接删除。单个文件被占用导致清理失败时跳过，留给下一次执行。
- 客户端（run_app.py）、独立 webserver（run_webserver.py）、下载器/导入器
  独立 CLI 运行时均自动启用；控制台输出行为不变，文件日志为额外增量。

## 左上角攻略浮窗

左上角常驻置顶的小窗口：顶部是一条**本地代码实现的细标题栏**（高 28 逻辑
像素，背景色与页面顶栏一致，非 HTML），标题栏下方是 pywebview 无边框网页
窗口（`frameless=True`，**没有任何系统标题栏**，并已去掉 Win11 的窗口圆角
与 1px 边框，与标题栏连成一体；Windows 上的渲染内核为 Edge WebView2），
直接显示 webserver 推送的攻略页面——内容与浏览器访问完全一致，底部导航栏
可用，游戏画面与攻略同屏对照。
网页区显示后会**监测 Chromium 渲染子窗口**（Chrome_RenderWidgetHostHWND）：
部分机器上 `hidden=True` 创建 + 直接显示的组合会让 Chromium 不创建渲染宿主，
网页区永久白屏——监测到缺失即自动做一次“隐藏→显示”循环强制其创建
（`background_color` 亦设为标题栏同色，初始化期间不再是白底）。

- **窗口默认停靠**屏幕左上角，**按住标题栏可拖动**到任意位置（图钉按钮照常
  点击）；呼出热区固定在屏幕左上角，与停靠点无关。
- **标题栏**：左侧显示当前展示的**章节名**——每秒优先读页面目录下拉的
  选中项（随翻页/跳章跟手，不依赖推送携带章节字段），读不到时退回 webserver
  推送的章节；最右边是一个“📌”图钉按钮。
- **图钉按钮语义**：
  - 已置顶（默认）：浮窗常驻显示，不自动隐藏。
  - 自动隐藏：鼠标离开浮窗约 0.6 秒后自动滑出屏幕左侧隐藏；呼出**只认屏幕
    左上角 8px 见方的热区**（与浮窗大小无关）；浮窗显示中时鼠标停在浮窗上
    则保持显示。
- **配置** `config/overlay.json`（修改保存即生效，加载失败沿用上次配置）：

  ```json
  {"enabled": true, "width": 320, "height": 640}
  ```

  `enabled: false` 时浮窗隐藏（命令行 `--no-overlay` 同效）；`width/height`
  是浮窗整体的 **CSS 逻辑尺寸**（与浏览器 DevTools 的手机模拟宽度同义，含
  28 逻辑像素标题栏），按系统 DPI 缩放换算成物理像素渲染——因此浮窗里的
  页面文字大小与浏览器同宽模拟时完全一致；修改后浮窗自动改变大小。
- 依赖 `pywebview` 与 **WebView2 运行时**（Win10/11 默认自带，无需安装
  Edge 浏览器本体）；缺失时浮窗打印原因退出，其余功能不受影响，页面仍可
  用任意浏览器访问。
- **生命周期跟随客户端**：浮窗是独立子进程，通过 Job Object（内核级，主进程
  退出时句柄关闭即全灭，强杀也生效）+ 进程内父进程看门狗（兜底）两道机制，
  保证客户端退出时浮窗自动终止，不会残留在桌面。

## 手机/平板扫码访问

手机/平板（安卓 / iPhone / 鸿蒙，平板同理）无需手动输入 IP：

1. 鼠标移到**显示器右上角**（热区默认 16px），扫码面板自动从右侧滑入，
   展示二维码与局域网地址（如 `http://192.168.1.5:22818`）。
2. 用手机/平板**系统相机**对准二维码即可识别并打开浏览器（标准 URL 二维码，
   三大平台无需分别适配），打开后页面随游戏画面自动跳转。
3. 鼠标从右上角移开（且不在面板上）约 0.5 秒后面板自动收回，默认不遮挡画面。

说明与限制：

- 面板平时完全隐藏，只有光标进入右上角热区才出现；弹窗提示出现时面板会自动
  排在弹窗下方，互不遮挡。
- **全屏展示**：点面板右上角「⛶ 全屏」，纯黑底**铺满整个屏幕**。二维码为
  **标准白底黑码**（兼容性最好），像一张白卡嵌在黑屏左侧，左/上/下边距各
  16px——即**等比例撑满整屏高度**（模块按整数像素重绘、锐利可扫，白底自带
  静区）；访问地址与来源标注为白色，在二维码右侧**垂直居中**（间距 16px），
  字号按剩余宽度自适应收缩、不挤压二维码。适合电视、会场大荧幕等远距离扫码
  场景。**多网卡（多张二维码）时右侧提供「◀ 1/2 ▶」翻页器循环切换**，键盘
  ←/→（演示翻页笔）同样可用。再点「还原」、点击二维码或按 Esc 恢复正常面板。
  全屏期间热角自动呼出与自动隐藏暂停，不会展示到一半被收走；退出后面板恢复
  并停留 3 秒再按常规逻辑自动隐藏。
- **双网卡（如有线+无线同时连接）**：面板会同时显示**前两个局域网地址的
  二维码**（各自标注地址，扫任意一个都能打开攻略页面），其余地址以文本列出；
  虚拟网卡（vEthernet/WSL/VMware 等）自动过滤，不占用二维码位置。
- 手机无法打开时先检查 Windows 防火墙是否放行了 22818 端口（首次启动时
  Windows 弹出的“允许访问网络”选择**允许**，或手动添加入站规则）。
- 二维码由 `qrcode` 库生成（已加入 requirements.txt）；缺失时面板只显示地址
  文本并提示 `pip install qrcode`。
- 相关参数：`--no-qr-panel` 关闭面板，`--qr-hotzone N` 调整热区大小（像素）。

## 游戏检测规则

1. 进程 GPU 3D 利用率 ≥ 20%，且 decoder、encoder 利用率 ≤ 10% → 候选游戏进程。
2. 进程名在 `exclude_processes.json` 中 → 跳过。
3. 进程名在 `game_processes.json` 中匹配到游戏名 → 该游戏。
4. 未匹配到游戏名 → 跳过。

## 常见问题

- **没有安装 Pillow / requests / beautifulsoup4**：执行 `pip install -r requirements.txt`。
- **截图不生效**：确认以管理员权限运行（部分游戏窗口 / 全屏独占模式下截图受限）。
- **命中率低**：调整 `--query-threshold`（默认 0.80）、`--match-score-threshold`（默认 0.7）
  或 `--confirm-hit-count`（默认 2）；也可在 `config/game_thresholds.json` 里按游戏单独配置阈值。
- **提示框反复弹出**：同一场景只推送一次，识别到其它场景后再回到该场景才会再次推送。
- **服务端 instance 被删除**：客户端查询失败时通过 vision list 接口
  （`/vision/service/list`）确认实例是否存在，**不存在则自动重新 insert + build**
  （约 2 分钟冷却，重建期间跳过识别；接口不可达时退回错误消息关键词判断）；
  本地攻略文件也缺失时自动退回完整下载+导入流程。
- **网页无法自动跳转/定位**：确认浏览器保持页面打开、webserver 端口未被防火墙
  拦截；电脑需能访问游民星空（`/proxy` 代替浏览器去抓取攻略页）。
- **frame 里图片不显示**：页面图片直接来自游民星空 CDN，电脑断网或 CDN 被拦时
  无法显示。
- **手机扫二维码打不开**：确认手机与电脑同一局域网（同一路由器，且路由器未开
  “AP 隔离”），并放行防火墙端口；多网卡电脑看面板上的“其它网卡”地址。
- **双网卡/多网段时部分设备访问不了**（如外网 192.168.1.x 能开、内网 10.x 打不开）：
  webserver 监听 0.0.0.0，所有网卡都在服务，通常是 Windows 防火墙按网络类型
  （专用/公用）拦截了入站。以管理员身份运行
  `python app/setup_firewall.py` 一键放行 22818 端口（`--port` 改端口、
  `--remove` 删除规则）；再用手机 ping 电脑内网 IP 确认链路互通。
- **设备与电脑不在同一网段时访问不了**：双网卡下默认路由若指向另一块网卡
  （如无线上外网），电脑回包会走错接口。需在电脑上加回程路由，例如设备在
  10.171.x.x、内网网关 10.172.16.1 时：
  `route add 10.171.0.0 mask 255.255.0.0 10.172.16.1`（加 `-p` 可持久化）。
